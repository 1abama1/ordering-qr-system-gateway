# Arduino Uno firmware

Скетч: `gateway/gateway.ino`. Arduino AVR Boards 1.8.6; ArduinoJson **6.21.5** (v6 сохраняет фиксированную память и рекомендован для 8-bit MCU). Рабочий цикл без delay, ограниченный serial budget, неблокирующий TX и watchdog AVR 1 с.

Проверенная компиляция Uno: 14822 байта flash (45%), 1224 байта глобальной RAM (59%), 824 байта остаётся для стека. Protocol literals находятся во flash через F()/PSTR(); очередь кнопок — фиксированное кольцо 16 событий. Это оценка компоновщика, а не измерение максимального стека на реальной плате.

```
arduino-cli core install arduino:avr@1.8.6
arduino-cli lib install ArduinoJson@6.21.5
arduino-cli compile --fqbn arduino:avr:uno firmware/arduino/gateway
```

По умолчанию только D2–D7 INPUT_PULLUP active LOW, debounce 30 мс. Моторные пины не назначены, MOVE_TO отклоняется NOT_READY, STATUS safe=false. Не прошивайте без проверки того, что D2–D7 свободны в вашей схеме. Upload автоматически не выполняется.

`HardwareConfig.h` и `HardwareAdapter.h` задают явный opt-in для линейного ENABLE/DIRECTION драйвера, шести дискретных датчиков и NC E-stop feedback. Для другой механики замените adapter; не переносите этот pinout вслепую. До включения REAL_HARDWARE нужно проверить уникальность и допустимость пинов, уровни, направление, торможение, датчики, внешнюю подтяжку ENABLE к OFF и токовые защиты. E-stop должен физически разрывать питание/разрешение привода независимо от микроконтроллера. Feedback — только наблюдение.

После boot/reset: FAULT BOOT_UNVERIFIED. Дождитесь стабильного единственного датчика, освободите E-stop, подтвердите RESET_FAULT и отдельный осмотр Gateway. HOME отсутствует: реального механизма homing не предоставлено. Время не подтверждает прибытие — только стабильный датчик target. Host timeout 3 с останавливает движение, movement timeout 14 с. Потеря backend не останавливает исправный локальный watchdog: текущая операция завершается по датчику либо по timeout, новые движения запрещены Gateway.

RX <=256 байт, output <=256 байт, один TX buffer; при перегрузке кнопки могут отбрасываться, seq показывает пропуски. ACK не означает прибытие. Последний commandId хранится в RAM для защиты от непосредственного replay; постоянная дедупликация и запрет retry после reset обеспечиваются Gateway ledger. Seq overflow требует reconnect (Gateway консервативно отклоняет меньшие seq).

Реальный мотор, схемотехника и поведение загрузчика при watchdog требуют стендовых испытаний. До них прошивка не аттестована для физического оборудования.
